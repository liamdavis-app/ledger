# Ledger — project notes

Single-file `index.html` gym/strength-tracking PWA. No build step, no framework, no git (yet). Monochrome aesthetic as of 2026-07-16: paper `#F5F5F7`, card `#FFFFFF`, ink `#1D1D1F`. The `--clay`/`--moss` CSS variable *names* are unchanged (too many call sites to rename for zero visual benefit) but now hold greys, not the old rust/moss hues: `--clay:#232326` (near-black, primary actions/strong emphasis), `--moss:#565A61` (steel-grey, data/progress accent). `SPLIT_COLOURS` and `groupColours` are now 5-/8-step greyscale ramps, not hues.

Working file: `index.html` in this folder. This is the only file that matters — edit it directly.

## Deploy workflow (manual every time — I can't do this part)
1. I edit `index.html` here.
2. You drag-drop `index.html` into the Netlify dashboard to deploy.
3. On your phone: fully close and reopen the app (not just background it) to clear cache. This is required — "changes not showing" is almost always a stale cache, not a bad deploy.

Netlify dashboard URL (`app.netlify.com`) ≠ the live app URL (`something.netlify.app`). Only the live URL goes on the home screen.

## Facts that cost real debugging time to learn — don't relitigate these
- Data lives in the phone's browser **localStorage**, keyed to the exact URL. It is never in the file itself, and deploying a new file does **not** touch stored data.
- iOS can silently clear PWA storage. If you ever re-add the app to the home screen, the **old shortcut may still exist pointing at the old storage** — check for a duplicate icon before assuming data is lost. (See Known Incidents.)
- `load()` only falls back to `SEED` when localStorage is empty — it never wipes existing data. Safe to re-run.

## Architecture
- `db = {library, splits, sessions, active, prefs}` → persisted to localStorage key `ledger_v1`.
- `load()`: reads localStorage → merges hardcoded `BACKFILL` sessions array (dedup by `id`, safe to re-run) → runs a repair migration that ensures every session's exercises exist in the library, guessing group via `guessGroup()` for any that don't.
- `SEED` (~85 entries after latest update): `['Exercise Name','Group']` pairs, grep `var SEED=`.
- `BACKFILL` (13 sessions as of 2026-07-07): hardcoded past sessions with fixed ids, grep `var BACKFILL=`.
- `GROUPS`: Chest, Back, Shoulders, Biceps, Triceps, Legs, Core, Other.
- `guessGroup(name)`: keyword matcher in `GROUP_KEYWORDS`, ordered by specificity.
- Five tabs: Today, Splits, Library, History, Progress.
- Bottom sheets via `openSheet()`/`closeSheet()`, drag-to-dismiss (`attachSheetDrag()`), keyboard-aware resize via `attachKeyboardResize()` (VisualViewport API).

## Feature inventory (shipped)
- **Progress tab** (2026-07-16 reorder): Lift explorer now renders first, directly under the title, above the timeframe selector — it's all-time data so it isn't gated by the timeframe filter. Personal bests (also all-time) comes next, then the timeframe selector, then the timeframe-scoped stats grid/insight/weekly-report-card. Previously the ranged-empty-state early-return hid the (all-time) explorer and PB sections too — fixed, they now always render regardless of the timeframe filter's result. Stats grid, headline insight card (`headlineInsight()`), collapsible accordion sections (state persisted to `db.prefs.accOpen`), timeframe selector (4wk/12wk/all-time), Muscle group balance, Training frequency heatmap, weekly report card (Mon–Sun, dismissable, split + exercise-level deltas) unchanged otherwise.
- **Lift explorer** (2026-07-08 redesign, `renderExplorer()`): picker collapses to a compact "[exercise] · Change ›" header once a lift is selected (`_pPickerOpen`), instead of always showing the full filterable list above the chart. Last 6 picks persist to `db.prefs.recentLifts`; a "Recent" chip row gives one-tap re-selection both in the collapsed header and the expanded picker. Split + muscle filters are tucked behind a single "Filters" toggle chip (`_pFiltersOpen`) that shows the active filter names even when collapsed, instead of three always-visible filter rows. Session log under the chart previews 5 entries with a "Show all N sessions" / "Show less" toggle (`_pLogExpanded`). 4 chart modes (1RM/top weight/top reps/kg-per-rep) are now a single-row `.scroller` chip strip (2026-07-16) instead of a 2×2 button grid, to save vertical space.
- **Chart rendering fix** (2026-07-16, `richLineChart()`): the SVG used `viewBox="0 0 500 200"` with `preserveAspectRatio="none"`, forced into a container of a different aspect ratio — this was the cause of the "squashed" look. Fixed by giving the container `aspect-ratio:500/280` (also taller than before) and dropping the forced non-uniform scaling, so the chart scales proportionally.
- **Sticky-header fade fix** (2026-07-16): `.top:after`'s fade gradient was positioned via `transform:translateY(100%)`, pushing it *outside* the sticky header's own box and into the scrolling content below — scrolled text was visibly legible through it. Fixed by keeping the fade inside the header's own painted area (extra `padding-bottom` + matching negative `margin-bottom`) instead of translating it out.
- **PB definition changed** (2026-07-16, `exPB()`): PB is now the heaviest weight lifted for 2+ reps, full stop — sets with fewer than 2 reps are excluded entirely, and the paired "Est. 1RM" figure is now the Epley estimate of *that same* PB set (previously PB text and the 1RM figure could come from two different sets, since the old ranking was by estimated 1RM, not raw weight — a session with 25kg×11 could out-rank a heavier low-rep set).
- **Splash screen** (2026-07-16): `#splash` full-screen overlay, inline SVG recreation of the "descending bars" icon as 3 `<rect>` bars, pure CSS keyframe animation (staggered `scaleX` reveal, ~0.86s), holds briefly then fades (~1.9s total, well under the 2–3s target), removed from the DOM entirely afterward (not just hidden) so it costs nothing post-load. Respects `prefers-reduced-motion` (skips the animation, shorter hold).
- **Library**: description field per exercise, live smart group-suggestion on new exercise names, session rename.
- **Picker (Add exercise)**: keyboard never covers the sheet, single clear "Create '[name]'" action, "create and add to session in one step" flow.
- **Rest timer**: removed entirely (was covering other buttons) — no trace left in code.
- **App icon**: "Descending bars" concept, base64-embedded PNG in `<link rel="apple-touch-icon">`, no separate asset file.
- **Live in-session stats**: live PB comparison vs all-time history, live kg/rep with % delta vs previous session, both recompute automatically on `toggleDone()`.
- **PB ranking unified** (2026-07-21): `exPB()` (historical) and the live "New PB" badge in `renderToday()` previously used two different ranking rules — historical ranked by raw weight, live ranked by estimated 1RM (weight×reps formula). A heavier set with fewer reps could score a *lower* estimated 1RM than an older higher-rep set, so the live badge silently failed to flag genuine new maxes. Fixed by extracting a single `bestWeightSet(sets, requireDone)` helper (heaviest weight wins, 2+ reps only, ties broken by more reps) used by both `exPB()` and the live comparison. Also fixes a related edge case: matching your best weight with more reps now correctly registers as a new PB (previously required *strictly* heavier weight).
- **Today landing redesigned** (2026-07-21, revised 2026-07-23): the no-active-session Today view is now a single primary CTA "Start new session" (`openStartSheet()`) which opens a sheet listing saved splits — tap one to start it immediately (`startSplit()`). "Create new split" and "Start blank session" sit below as secondary/dash-style buttons. Superseded the earlier "list all split cards directly on the landing page" version and the "three equal-weight buttons" version — this is the current one. Today tab was already leftmost in the bottom nav; no change needed there.
- **Splits tab ordering fixed** (2026-07-23): `renderSplits()` was rendering the "+ New split" button *before* the list of existing splits — so opening the Splits tab put "New split" as the first, most prominent thing, ahead of splits you'd already saved (e.g. reaching a saved "Legs" split felt like it required going through "New split" first). Fixed by moving existing splits to render first, "+ New split" moved to the bottom of the list.
- **Today/Splits tab overlap removed** (2026-07-23, "Option B"): both tabs used to let you *start* a split, which felt redundant. Splits tab's "Start" button removed — `startSplit()` is now only ever called from Today. Splits tab subtitle updated to "Manage your splits — start a session from Today" to make the division explicit. In exchange, Today's "Start new session" sheet (`openStartSheet()`) gained a pencil edit icon per split row (new `pencil` icon in the `IC` map) that calls `editSplit(sp.id)` directly via `event.stopPropagation()` so it doesn't also trigger `startSplit()` — covers the common "quickly add an exercise to today's split right before starting" case without leaving Today. The Splits tab remains for the rarer full edits (rename, delete, reorder, default set counts).
- **Group-aware, frequency-ranked exercise picker for splits** (2026-07-23): `pickForSplit()` (the "Pick from library" step when building/editing a split) now defaults the picker's group filter based on the split's name via `guessGroupFromSplitName()` (substring match against `GROUPS`, e.g. "Legs"/"Leg Day" → Legs; ambiguous names like "Push Day" fall back to "All", unchanged behaviour). Within a specific group filter, `drawPickList()` now sorts exercises by how often each has been logged in past sessions whose *session name* matches that group (`exerciseFreqInGroup()`/`sessionsMatchingGroupName()` — e.g. "Legs"-named sessions), not alphabetically. Falls back to alphabetical for ties or zero-frequency exercises. `openPicker()` now accepts an optional `filter` in its opts to set the initial chip; unaffected call sites (e.g. `addExtra()`) still default to "All".
- **Today landing top-spacing fixed** (2026-07-23): the "Start new session" redesign (above) dropped the old `.card` wrapper (17px own padding) that used to buffer the first button from the sticky `.top` header's fade-overlap zone (`.top` uses a `margin-bottom:-14px` trick so its fade gradient paints over the following content — see the 2026-07-16 sticky-header fix). Without the card, the button sat almost flush against the header, looking "cut off." Fixed with `margin-top:10px` on the primary button specifically — scoped to Today's landing only, not a global `.top`/`.wrap` change.
- **"Build splits from history" — one-time recovery/setup tool** (2026-07-23): discovered that a user could have months of session history consistently named via `renameSession()` (e.g. "Legs", "Back and Biceps", "Chest and Triceps", "Shoulders and Arms", "Mix" — the *actual pre-existing categories in this app's real backfill data*) without ever having created matching `db.splits` entries — `db.splits` (used by the Today/Splits tab flow) and session names in `db.sessions` are two separate, previously-disconnected pieces of data, so the Splits tab can legitimately be empty even with rich matching history; this is not data loss. Added `sessionsByName()`, `candidateSplitNames()` (session names logged 2+ times with no matching split yet), and `buildSplitsFromHistory()` (creates one split per candidate name, exercises ranked by how often logged — 2+ occurrences preferred, falls back to whatever's there if nothing recurs — capped to 8, default sets = median sets logged for that exercise). Surfaced as a "Build N splits from history" dash-button in `renderSplits()`, shown only when candidates exist; self-resolves (button disappears) once built. Idempotent — re-running never duplicates existing splits.
- **Off-split exercises grouped** (2026-07-21): exercises added via `addExtra()` mid-session are now tagged `extra:true` and, when the active session came from a split (`a.splitId` set), rendered in a separate collapsible "Added outside this split" section below the split's core exercises, grouped by muscle group (`GROUPS` order). Collapsed by default (`_extrasOpen`, not persisted — resets each app load). Sessions started blank/custom have no grouping distinction (flat list, as before).
- **Header cut-off bug fixed for real, not per-tab (2026-07-30)**: root cause found — `.top`'s `margin-bottom:-14px` (used so its fade gradient bleeds onto scrolling content) pulled *every* tab's first element up 14px into the header's own painted area, permanently hiding its top edge, not just during scroll. The 2026-07-23 fix only patched Today's "Start new session" button (`margin-top:10px`, now removed) instead of the root cause, which is why it kept resurfacing on other tabs. Fixed once, globally, with `#app{padding-top:14px}`.
- **"In Focus" banner no longer stuck (2026-07-30)**: `headlineInsight()` always returned candidate #1 from a fixed-priority list, and candidate #1 was "biggest all-time 1RM % gain" — a lifetime first-vs-last comparison that only ever grows, so one lift locks in as "best" forever. Fixed: (1) swapped the metric to kg/rep (Liam's preferred metric over 1RM), using a recent-window comparison (last 2 sessions vs prior 2) instead of lifetime first-vs-last, so whichever lift is trending *now* can take the slot; (2) added day-seeded rotation (`dateHash(todayStr())%candidates.length`) across whichever candidates qualify, so the banner shows variety instead of always the same priority-#1 type, while staying stable within a single day.
- **Lift Explorer rebuilt as a swipeable card carousel (2026-07-30)**: replaced the collapsed-row-plus-"Change ›"-expand-to-grouped-list picker (two redesigns already, still reported clunky) with a horizontally swipeable, scroll-snapped rail of lift cards (`.liftrail`/`.liftcard`, `renderExplorer()`), each showing name, PB, and a kg/rep mini-sparkline (`miniSparkline()`) — recents first, then the rest. Tapping a card loads the full chart/log below (`renderProgressLift()`, unchanged). Search + a Split/Muscle "Filters" toggle stay always-visible above the rail (no more expand/collapse mode toggle — `_pPickerOpen` state removed entirely, along with the now-dead `recentLiftsChips()`). Default chart mode changed from Est. 1RM to Kg/rep (`_pMode` default), matching the metric Liam actually tracks.

## Known incidents
- **2026-07 data loss (resolved)**: re-adding the app to the home screen after a deploy created a second shortcut pointing at fresh/empty storage, while the original shortcut still held the real sessions. Recovered via History → Export from the old shortcut. Verified recovery: all 13 sessions cross-checked byte-for-byte (id/date/name) against `~/Downloads/ledger-2026-07-02.json` — confirmed complete as of 2026-07-07.
- Takeaway: if data ever looks missing, check for a duplicate home-screen icon before assuming it's gone.
- **2026-07-23 "empty Splits tab" scare (resolved, not data loss)**: user reported 5 known splits (Legs, Back and Biceps, Chest and Triceps, Shoulders and Arms, Mix) missing from the Splits tab. Root cause: `db.splits` (reusable templates) and session *names* in `db.sessions` (set via `renameSession()`) were always two separate, disconnected pieces of data — the user had been naming sessions consistently for months but had never used "New Split" to create matching template entries, so the Splits tab was correctly empty, not broken. Ruled out duplicate-icon and wrong-URL causes first (same home-screen icon, confirmed). Fixed by building "Build splits from history" (see Feature inventory) rather than manual recreation. Takeaway: before assuming data loss, check whether the "missing" thing was ever actually the same data store as what still looks present elsewhere (here: History tab still had everything, because it reads `db.sessions`, not `db.splits`).

## Standard workflow for changes (keeps token use down — follow this, don't re-derive it)
1. Read only the relevant section of `index.html` before editing (it's long — don't read the whole file unless necessary).
2. Edit with targeted `Edit` calls.
3. Syntax check: extract the `<script>` block and run `new Function(js)` in Node.
4. Duplicate-function-name check via regex on `function NAME(`.
5. Logic smoke test (session counts, group assignments, id dedup) via a small Node script — cheaper than Playwright for data-model changes. Use Playwright only for actual UI/rendering changes.
6. Remind the user: deploy to Netlify, then fully close and reopen the app on the phone.
7. Update this file's "Feature inventory" / "Open / in progress" sections to reflect what shipped.
